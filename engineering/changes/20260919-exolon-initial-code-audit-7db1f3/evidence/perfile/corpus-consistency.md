# Согласованность самого аудит-корпуса (corpus-consistency lane)

**Объект:** не игра, а связность доказательного корпуса: `exolon-initial-audit.md` (v1, 442 строки) +
`exolon-initial-audit-backlog.md` (v1-bl) + `exolon-full-audit-20260920.md` (v2, авторитет) + пакет
`engineering/changes/20260919-exolon-initial-code-audit-7db1f3/` (typed-спека, requirements, tasks,
test-plan, rollback, release, architecture, state.json, route.json) + `evidence/**` +
`.grok-stack/runtime/receipts/7db1f3f0b126/**` + `.grok-stack/runtime/approvals.json`.

**База:** HEAD `52795d1`, рабочее дерево `<repo>`. Снимок доказательной базы на
момент записи: `evidence/` = 37 файлов (19 верхнего уровня + 18 полос в `perfile/`), `perfile/` =
141 локальных ID в 8 префиксных пространствах. Каталоги живые — соседние полосы дописывают файлы во
время моего прогона, поэтому счётчики полос помечены как снимок.

**Read-only:** записан ровно этот файл. `git status --porcelain | grep -v '^??'` → пусто (проверено
до и после). Ни один измеритель не запускался из каталога evidence (они пишут рядом с собой:
`fullaudit_measurements.py` перезаписал бы `fullaudit-b01-spawn.json`, `linux_static_audit.py` —
`linux-static-audit.{md,json}`, что само по себе сломало бы побайтную сверку). Все пересчёты —
собственный read-only python по `Exolon/Resources/*.tmx`, `Exolon/**`, гит-объектам и JSON-квитанциям.
C1-геометрия не пересматривается (урегулировано дважды) — только то, как о ней написано в документах.
