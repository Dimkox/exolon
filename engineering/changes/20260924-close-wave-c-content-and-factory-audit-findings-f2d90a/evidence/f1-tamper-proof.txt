## What this proves
- The reviewer's shipping cases **C10** (`L02S16.background` -> a file that does not exist) and
  **C11** (`L02S16.background_sha256` -> fabricated 64-hex), which previously produced
  `ALL_WAVE_C_PROBES_PASS, rc=0` across the entire net, now fail `manifest_selfcheck`.
- **K10/K11/K12 re-seal with the real embedded key**, i.e. an attacker who read
  `wave_c_check.py` and recomputed the digest correctly: still red, because
  `validate_manifest` now re-derives every data claim from `Exolon/Resources` (per-map canonical
  digest, backdrop name, backdrop bytes via the renderer's basename resolution, layer count, and
  hash-equality of each declared pair) instead of trusting the file's own numbers.
- `manifest_selfcheck` previously called `validate_manifest(manifest)` with no corpus, so the
  corpus branch was dead in the probe; it is now mandatory (the parameter defaults to a fresh
  recomputation, so even the generator path cannot skip it).
- Restoring the authentic contract returns the net to green, so the detections are not
  over-strictness.

## Honest limit of the digest (also stated in the probe output as `binding_limit`)
A keyed digest in a public repository is a *construction* barrier, not a cryptographic one. What
it genuinely buys: the old 'edit a value + recompute sha256(body)' path is rejected. What it does
NOT buy: a forger who reads INTEGRITY_BIND can still re-seal **prose** fields (ruling wording,
pair_notes text). Those are defended by `level_pair_manifest_pinned` asserting the disclosures
exist and by the blob-identity check on `Exolon/Resources`, not by the digest. No doc in this
package may claim body_sha256 protects wording, and INV-001's 'bound transitively' language is
read with that limit in mind.
