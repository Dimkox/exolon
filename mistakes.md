# Mistakes

## 2026-09-24: Lane maps restated at call sites silently rot, and a contract-sync script that writes `None` is worse than one that crashes

Wave A shipped four wire lies (`damage.player_hit`, `damage.player_blocked`, `state.checkpoint_saved`, `state.restart`: wrong lane order, a formatter decoding a lane no producer filled, a 17-bit pack in a 16-bit lane) because the lane layout was written four times per record - schema text, `GameplayEventKind.schemas`, the formatter's decoder, the call site's packer - and only one of those copies was ever executed: the call sites live in SpriteKit-bound files that the Linux gate does not compile, so a green 23/23 suite certified the formatter while the producers were unproven. Root cause is structural, not careless: **a repeated encoding is an unenforced equality**, and **coverage of the decoder was reported as coverage of the design**. The fix has to be structural too - one producer helper per wire name in a compiled file, call sites forbidden from touching lanes, and a table-driven round trip (pack → format → parse → compare every field) that fails for every one of the four shapes; plus a parse gate over the touched SpriteKit files so they cannot be silently broken.

Second, self-inflicted: the throwaway script that re-synced `x-encode` from the Swift table did `lanes.get(str_key)` against `{int: str}` and, finding `None`, *wrote* `None` into 44 contract fields instead of aborting - a silent contract corruption that only survived because a check compared the texts. Any script that rewrites a frozen artifact must assert the lookup succeeded (index, do not `.get`) and must leave the artifact untouched on failure.
